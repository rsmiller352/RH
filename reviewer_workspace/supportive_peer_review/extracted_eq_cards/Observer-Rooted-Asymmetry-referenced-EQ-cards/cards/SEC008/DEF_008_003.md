## 1) Plain language

RO-A built the **reader** (the locus L) and the **collection** it ends up with (𝖣(L), an unordered set of
already-resolved completions). But RO-A deliberately stopped short of saying **what the act of registering
actually is** — it only *named* it. This card supplies exactly that one missing thing: **registration is the
act of making an already-resolved completion available at the reader.**

Concretely: take a completion u that the substrate already resolved (its action-gap reached a full unit —
that is the aperture's doing, not the reader's), and an observer locus L. **reg(L, u)** simply says: *u is
available at L* (it belongs in L's collection 𝖣(L)). That is the whole operation — a **yes/no membership**:
this completion is registered at this locus, or it is not.

Two things this card is careful **not** to do. **First, it does not order anything.** Registration says
*which* completions are available, never *in what order*, never *which came first*, never *how many steps
along*. The collection stays the unordered set RO-A already fixed. Putting the registrations in an order, or
reading them as a measure, is a **separate, later** job (clockhood). **Second, registration does not create
or resolve anything** — the completions were already resolved internally; reg only makes the already-resolved
ones available. It adds nothing to the books, it is not a second aperture, and it never reaches back to change
the finished internal record. It only reads.

So this is the bare operation of the readout side: *register = make an already-resolved completion available
at a locus*, a plain membership relation, carrying each completion's orientation tag. Ordering, timing,
calibrating, pricing in energy, predicting — all deliberately left for the obligations that come after.

## 4) The defined object & its type (DEF content)

- **The object:** the **registration relation reg** — a typed **membership/availability relation** between an
  observer locus L (DEF_008_002) and an already-resolved completed update u (DEF_S06_002/THM_S05_007). reg is
  the *operation* (the act of registration) that RO-A named; its image at L is 𝖣(L).
- **Its meaning:** reg(L, u) holds ⟺ u is distinguishable at L's scale and registered/available at L ⟺
  u ∈ 𝖣(L). The relation **populates** 𝖣(L); it does not construct a new set (𝖣(L) is DEF_008_002's,
  unordered, consumed).
- **σ discipline:** each holding registration carries u's σ (THM_007_005), separate; reg neither erases σ nor
  recovers it from magnitude / phase / any cost.
- **Availability, not creation (the A↔B seam, carried from RO-A):** reg makes **already-resolved** content
  available; it does **not** create / resolve / ground distinguishability (AX_001_001 primitive; A_Φ /
  THM_006_007 internal resolution — **unweakened**), and does **not** re-resolve the record. Only u with
  |g_Φ| ≥ 1 (THM_006_007) are registrable.
- **UNORDERED (the membership-not-ordering fence — the RO-B↔RO-C seam):** reg is a **yes/no** per (L, u). It
  imposes **no** order / sequence / succession / before-after / position-comparison / registration-history /
  ordered measure. 𝖣(L) = { u : reg(L,u) } stays the **unordered** set (DEF_008_002). *Ordering the
  registrations — "read as an ordered measure" — is **RO-C (clockhood)**, OPEN; doing it here is F-S07B-1.*
- **Direction:** reg is **downstream** (S07 readout). It reads the already-resolved record and **grounds /
  edits / reopens nothing**; DEF_008_002 / GATE_008_001 / S06 are **unedited** (DEF_005_012 direction;
  the D-064 status boundary).
- **What reg is NOT (the type boundary):** not an ordering / sequence / measure / clock (RO-C); not physical
  time / rate / duration (RO-D); not κ (RO-E); not energy / a cost-as-energy (RO-F); not a prediction (RO-G);
  not a creator/resolver of distinguishability nor a second aperture (the A↔B seam). Reading any of those off
  this card is out of scope (TD-020 / TD-011).
