# Architecture locks & guards — internal-accounting-only; k ≠ n ≠ t (update/event/physical-time indices distinct); runtime-not-physical-time/energy; dependency-direction lock (ledger → state → record → readout); residual persistence; pre-readout compile lock (the fence S06 satisfies, not deletes)

## 0) Governance & Scope Lock

Definition card: states the runtime layer's architecture locks and well-posedness conditions — the
index distinctions (k ≠ n ≠ t), the runtime-not-physical-time/energy fences (instancing
GUARD_S02_016/018 at runtime, TD-013), the dependency-direction lock, residual persistence, and the
pre-readout compile lock. The locks are the fence S06 SATISFIES, not deletes. Exact forms only.
Residual persistence re-typed per §0 (strictly-positive holding retained, never a zero value). Layer
ceiling S04.

## 1) Plain language

This page is the runtime's rulebook for staying well-behaved. Three different counters must never be
confused: the update index (which cycle), the event index (which tick), and physical time (which the
runtime does not have). No runtime quantity is a duration or an energy — those are translation-map
claims for later bridge cards. Information flows one way only: ledger to state to record to readout,
never backward. The residual register keeps its leftover (a strictly-positive holding) rather than
being wiped to zero — and when a discharge empties it, it leaves the book cleanly. And the
trajectory is fully determined by its start, so the whole schedule can be recomputed. Every one of
these is a fence the later sections must respect, not erase.

## 2) Statement

**(1) Internal-accounting-only.** The runtime layer books internal accounting; no external/physical
quantity is read here (P7's readout discipline; the units-bearing exit is BRIDGE-only,
GUARD_003_008 instanced).

**(2) k ≠ n ≠ t (the index lock, P2).** The update index k (cycle), the event index n (tick), and
the physical-time index t are DISTINCT — never conflated (the GUARD_003_006 instance at runtime: the
runtime axis is bookkeeping, not physical time).

**(3) Runtime-not-physical-time/energy.** No runtime quantity is physical time or energy
(GUARD_S02_016/018 instanced at runtime; P5/TD-019). The mapping to measured quantities is a BRIDGE
obligation, not a runtime reading.

**(4) Dependency-direction lock.** Information flows ledger → state → record → readout, NEVER
backward (the pre-readout compile lock: every readout-side parameter is downstream of the compile
lock; DISC_RUNTIME_007 / EQ_09_001's separability seam).

**(5) Residual persistence (§0 re-typed).** The source register is NOT cleared to a zero value: it
**retains a strictly-positive holding when present**, and the discharge empties it by LEAVING THE
BOOK (register-absence, DEF_005_003), never S_res = 0. The residue carries forward (DEF_005_011's
update rule).

**(6) Well-posedness (PC-014, motivation).** The runtime trajectory is a deterministic function of
its start (initial residual triad, ω_cell), so the schedule is recomputable (P12-friendly). Carried
as well-posedness motivation; the L05-family sweep (GAP-S04-N) is OWED before PC-014 grounds
anything.

## 4) Well-formedness (DEF obligation)

- **The index lock is consistent.** k, n, t are distinct typed indices; the runtime cards (#2–#14)
  use k (cycle) and the tick index n (event); t (physical time) appears NOWHERE as a runtime
  quantity (only as the named exclusion). The lock is well-formed (it partitions the index roles).
- **The fences INSTANCE, not restate (TD-013).** Locks (2)/(3) instance GUARD_S02_016/018 at the
  runtime layer — the card RELIES on those guards' prohibitions to be well-formed (it extends them
  to runtime quantities), so the dependency edges are validity-reliant (D-029.3); it does not
  restate the guards' content as litany.
- **The dependency direction is acyclic.** The runtime dependency DAG is acyclic (validator-checked);
  the pre-readout compile lock makes every readout parameter downstream of the compile lock — no
  backward edge in the sense that matters (no readout result feeds back into the ledger/state it was
  computed from).

  **The correct runtime LAYERING (the four-role "ledger → state → record → readout" model is a COARSE
  abstraction; the genuine DAG has more structure — documented here so a witness layer-model is not
  mistaken for a card defect).** The genuine dependency relationships:
  - The DISCHARGE (THM_005_010) is a RECORD-layer theorem that the UPDATE RULE (DEF_005_011) legitimately
    CONSUMES: the update composes the proved discharge into a recurrence. So DEF_005_011 → THM_005_010 is
    a CORRECT edge (the update sits ABOVE the discharge, not below it). Reading DEF_005_011 as pure
    "state" under the coarse model mis-classifies it: it is a state-update that consumes a record-layer
    theorem.
  - The FROZEN MODULE (DEF_S04_014) is a RECORD/golden-vector object that legitimately TESTS the READOUT
    theorems (THM_S04_010/012/013): golden vectors freeze and check the readouts. So DEF_S04_014 →
    THM_S04_010/012/013 is a CORRECT edge (the frozen module sits ABOVE the readouts it freezes). Reading
    DEF_S04_014 as pure "record" under the coarse model mis-classifies it: it is a golden-vector module
    that consumes the readout theorems it certifies.
  - The FORCING (THM_005_009) is the deepest "why a posting must happen" and depends on the account
    typing (DEF_005_005) + the posting typing (DEF_005_004); the DISCHARGE (THM_005_010) consumes the
    forcing (THM_005_010 → THM_005_009, D-049 strengthening). So the record layer itself has internal
    order (forcing upstream of the discharge that books it).

  These are CORRECT dependencies — a witness whose coarse "ledger ≤ state ≤ record ≤ readout" role map
  flags DEF_005_011 → THM_005_010 or DEF_S04_014 → THM_S04_010/012/013 as "backward" is mis-classifying
  the layer of the consuming card, NOT detecting an inverted card edge (NOT an F-104 / TD-012 defect).
  The WITNESS LAYER MODEL must be refined (note for the witness author, §9): assign DEF_005_011 a role at
  or above THM_005_010 (it consumes the discharge), and DEF_S04_014 a role at or above the readouts (it
  freezes them); the genuine acyclicity is validator-checked on the real DAG.
- **Residual persistence is strict-positivity-typed.** 'The source is not cleared' is the register
  retaining a strictly-positive holding (when present) or leaving the book (on discharge) — never a
  zero held value (§0; GUARD_005_008).
