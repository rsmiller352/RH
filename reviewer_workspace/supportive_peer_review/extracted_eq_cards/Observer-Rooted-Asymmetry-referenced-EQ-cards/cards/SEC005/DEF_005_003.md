# The runtime residual register S_res — a PARTIAL holding (DEF_002_001 as amended); the runtime state tuple State_rt, arity resolved; strictly positive when present, leaves the book when emptied (§0 re-typing)

## 0) Governance & Scope Lock

Definition card: types the runtime residual register and the runtime state tuple, and
nothing else — no valuation, no recurrence, no discharge (those are #4–#9). Exact symbolic
forms only. The register is a PARTIAL holding (DEF_002_001 as amended): strictly positive
when present, absent when emptied — no zero value anywhere. The minimal tuple is
(S_res(k)); scheduler coordinates are reserved (Q-A). Layer ceiling S04.

## 1) Plain language

The runtime needs one place to hold its leftover: the residual register. It is not a
number that can sit at zero — it is a holding in the book, and like every holding in this
framework it is strictly positive whenever it is there at all. When the running cycle has
some residue waiting, the register holds it (a strictly-positive amount, always less than a
whole unit). When a discharge empties it, the register simply leaves the book — there is no
"the register now reads zero"; there is "the register is not in the book until residue
accrues again." The runtime's whole state, at the core layer, is just this one register's
holding. Earlier work disagreed on how many slots the state had; this page settles it: one,
in core runtime, with the scheduler's extra coordinates parked for a later, conditional
subsection.
