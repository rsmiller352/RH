# Zero exclusion — the boundary rule (declared import of EQ_01_002)

## 0) Governance & Scope Lock

This card may be cited as the spine's zero-exclusion rule and for nothing else. Dependent

## 1) Plain language

Zero marks the edge of non-existence. It is a label for "nothing there," and nothing can be
built on it: no card may treat "nothing" as a thing, quantify over it, or assign it as the
value of something that exists. Zero keeps its ordinary formal jobs — an empty register may
read 0, a sum may cancel to 0 — but as a statement about existence, 0 is a boundary, never
a state.

## 2) Statement

**Imported boundary rule (EQ_01_002, verbatim):** "0 denotes non-existence and is not an
admissible state value for existence-typed objects; admissible existence-typed objects are
never identified with 0."

Restated for this spine: 0 is a boundary/formal label only; the zero state of I is not a
discussable, derivable, or referencable state (P1).

**Condition A (F-151, stated as required):** event counts of admissible distinctions are
existence-typed. (This is the typing judgment that carries the boundary rule to

**Condition B (F-151, stated as required):** "existence-typed" is grounded on AX_001_001's
axiom — the named primitive precedes this rule — never on any forcing theorem. This card's
two dependency edges implement the re-grounded order (AX_001_001 → THM_002_007 → this card).

**Licensed formal roles of 0 (scope clause, merged from Gen-2):** additive identity
(0_𝒟 of DEF_002_001's cone), absence-marker (an empty register's holding), boundary
readout, reference label, limit value, cancellation result. In particular, holdings with
